# DUB-200 — industrial generative DUB-1 fork for the M-VAVE FM-1

DUB-200 is a development fork of **[FM1 Dub v1.3.0](https://github.com/sbegueria/fm1-dub/tree/v1.3.0)**. It keeps the things that make DUB-1 powerful for a one-box jam: chord-memory stabs, unequal FM ping loops, a scale-aware bass line, phrase-based drums, dub echo, the eight-bar arrangement, and the **Evolve** / **Motion** controls. It extends the tempo ceiling to 200 BPM and adds a small, deliberately bounded user-sample overlay system without changing DUB-1’s original factory pieces or sound engine.

This is not affiliated with M-VAVE, Warp Records, Aphex Twin, Squarepusher, or the original DUB-1 authors. It is a GPL-3.0-only derivative and retains the required upstream notices in `LICENSING.md`.

## What the fork changes

| Area | DUB-200 behavior |
|---|---|
| Tempo | **90–200 BPM**. The original default remains 122 BPM; 200 BPM is available from the existing Key page tempo control or HOME + SELECT gesture. |
| Factory pieces | DUB-1’s original Basic, Chamber, Steppers and other piece recipes are unchanged, so existing familiar sounds and projects behave as before. |
| Generation | Retains DUB-1’s evolving chord, ping, bass, hat, kick and phrase-arrangement generators. **Evolve** changes their decisions over time; it does not repeat a static MIDI clip. |
| Screen | DUB-200 identity on the splash/crash/safe-mode screens; the familiar DUB-1 UI palette and font remain unchanged. |
| User audio | Ten independent flash-backed one-shot slots: **A and B for each of the five DUB layers**: Chord, Pings, Bass, Drums and Noise. |
| Per-piece choices | Each layer in each saved piece has an **Off / A / B / Alt** selector. `Alt` alternates that layer’s two slots each time it is triggered. |

## Does it auto-generate and evolve the rhythm?

Yes. That is inherited from DUB-1, not added as a static pattern player. On each phrase and bar it can evolve the kick shape, bass plan, shuffled hats, pings, noise groove, section (Full / Break / Groove / Thin), occasional fills and chord changes. **Evolve**, **Motion**, **Drift**, layer density controls, the Pattern page, and PERFORM Lock determine how much it changes.

DUB-200’s user samples follow those generative events:

- **Chord A/B** retriggers with a generated chord stab.
- **Pings A/B** retriggers with the FM ping loops.
- **Bass A/B** retriggers with generated bass notes.
- **Drums A/B** retriggers with kick-grid hits only, so hats do not constantly restart a long sample.
- **Noise A/B** retriggers with generated noise events.

That makes a short metallic hit, room tone, clipped amen hit, impact, vocal grain or found sound participate in the machine’s existing generative logic. In this first implementation they are **overlays**, not replacements for the native synth/drum layer: the original DUB-1 voice remains audible below them. This keeps all DUB-1 pieces working and avoids changing its mix architecture.

## Capacity and sample format

The FM-1’s 1 MiB flash has an unused safe region from `0xA0000` through `0xDC000`; DUB-200 reserves it as ten 24 KiB independently erasable slots. It ends before Felucca/DUB-1’s panel-calibration data at `0xDC000`, and is outside both the project store and the OTA staging area.

| Item | Limit |
|---|---:|
| Slots | 10 (five layers × A/B) |
| Slot payload | 24,320 bytes (24 KiB slot minus committed header) |
| Playback file | mono unsigned PCM8, 11,025 Hz |
| Maximum playback per slot | **2.21 seconds** |
| Resampling | linear interpolation to the FM-1’s 44.1 kHz output |
| Runtime memory | fixed one voice per layer; PCM stays in flash/XIP, not RAM |

The importer converts normal WAV/AIFF/FLAC/MP3/etc. through FFmpeg. For rhythmic samples, prepare a short, tightly cut hit or loop fragment. Long loops should be made externally as a short looped phrase; version 0.1 is a one-shot overlay player, not a tempo-warping loop engine.

## Selecting slots on the FM-1

1. Open the normal page of the target layer: **ENV** Chord, **ARP** Pings, **LFO** Bass, **SEQ** Drums, or **SAVE** Noise.
2. Hold **GLO** and turn the **PRESETS** encoder.
3. The display says the layer and selected value: **OFF**, **A**, **B**, or **ALT**.
4. Hold **GLO** normally to save. The selection belongs to the currently active DUB piece; the PCM slot itself remains global.

The existing PRESETS encoder still changes pieces when GLO is not held. The new gesture marks GLO as used, so releasing it after a slot selection cannot accidentally reset or save the piece.

## Uploading a user sample

The firmware accepts compact USB-MIDI SysEx frames under the non-commercial `0x7D` manufacturer ID. Use the included uploader; it checks acknowledgements from the FM-1 after every frame and does not write a slot without an explicit number.

```bash
cd /path/to/dub200-fm1
python3 -m pip install mido python-rtmidi
python3 tools/dub200_samples.py --list

# Slot 6 = Drums A. The tool converts the file, asks the device to erase only
# that slot, streams it in verified packets, then device-verifies its CRC.
python3 tools/dub200_samples.py --slot 6 --name metal-hit --input metal-hit.wav
```

If the source converts beyond 2.21 seconds, trim it first, or explicitly accept the first 2.21 seconds:

```bash
python3 tools/dub200_samples.py --slot 6 --name clipped-break --input break.wav --trim
```

To erase a single global slot:

```bash
python3 tools/dub200_samples.py --clear 6
```

### Import safety behavior

Importing or clearing stops the transport and panics voices before flash erase/program operations. It erases **only** the selected 24 KiB region. A slot header is committed last, after a full device-side CRC check, so an interrupted or failed transfer reads as an invalid, silent slot at the next boot. It does not write the firmware image, OTA region, normal DUB project objects, settings, or panel calibration.

Do not disconnect power during an upload. If it is interrupted, re-upload that one slot; no DUB project is affected.

## Build and install

Build from this source tree with the DUB-1/Felucca documented AC79 SDK and JieLi toolchain setup in [`BUILDING.md`](BUILDING.md):

```bash
./build.sh
# development package: build/amb.fwsc
# release identity/package: python3 tools/build.py --release 0.1.0
```

A release invocation currently produces `build/dub-0.1.0.fwsc` because it retains upstream package naming; its on-device splash and screen-reader identity are DUB-200. Install only a package that has passed the target build and installer tests, and keep M-VAVE’s official recovery/update procedure available. Custom firmware flashing always carries some risk.

## Engineering constraints and next steps

The implementation intentionally keeps its FM-1 realtime boundary narrow: one active PCM voice per DUB layer, no allocation, no file decoding, no flash writes in the audio or USB interrupt, and no flash-sector access while the transport is running. The natural next releases are a per-layer wet/replace mix control, short loop points, source-level sample envelopes, a browser importer, and a true fast 160–200 BPM break/jungle piece bank.
